# 타비도리 — 도메인과 원칙

## 누가 무엇을 위해 쓰나

**일본 여행을 계획하는 한국인 개인 여행자.** 하루 일정을 짤 때 쓴다.

타비도리는 일정을 **자동으로 만들어 주지 않는다.** 사용자가 직접 고른 스팟 조합으로 가능한 순서를 **검증**해 보여주는 "검증형" 서비스다(2026-09-08 피벗). "좋은 일정"은 주관적이라 검증할 수 없지만, "휴무일에 가지 않는가·마감 전에 도착하는가"는 검증할 수 있다.

## 원칙 — 설계 판단의 근거로 계속 쓰인다

| 원칙 | 뜻 |
| --- | --- |
| **추측 금지** | 확인 안 된 정보는 확인 안 됐다고 표시한다. 그럴듯한 추정치를 보여주지 않는다 |
| **승인 없이 바꾸지 않는다** | 시스템이 스스로 스팟을 빼거나 바꾸지 않는다. 계산해서 보여주고 선택은 사용자 몫 |
| **화면 배치는 AI, 숫자·판정은 검증기** | Claude는 무엇을 보여줄지 고르고, 그 안의 이동시간·판정·휴무는 결정론적 코드와 외부 API가 채운다 |
| **에이전트가 하는 일은 좁다** | 하드 제약 판정은 규칙 코드. LLM 판단은 비정형 공지(임시휴무 등)를 읽는 곳에 쓴다 |

## 용어

| 용어 | 뜻 |
| --- | --- |
| 스팟 | 일정에 넣는 장소. **큐레이션 스팟**(팀이 조사한 관광지, DB) / **자유 검색 스팟**(식당·카페 등 Google 장소 검색) |
| 트레이 | 사용자가 담은 스팟 목록(하단 카드 줄). 순서를 드래그로 바꾼다 |
| 검증 | 트레이의 순서로 하루를 계산해 제약 위반을 찾는 것 |
| 하드 제약 | 휴관일 충돌 · 마감 후 도착 · 마감 시각 초과(총 소요시간) · 비 올 때 실외(강수확률 70% 이상, 16일 안 날짜만) |
| 패턴 | 결과 화면의 순서 후보. "내 순서" + 위반 없는 다른 순서 최대 2개(A·B) |
| Loop A | 임시휴무 확인. 공식 페이지 → (애매하면) 웹검색 → (그래도 불명확하면) 확인 불가. 배지 6종으로 결과 표시 |
| Loop B | 확정 후 출발 전까지 주기적으로 다시 확인하고, 문제가 생기면 알림 |
| 확정 | Google 로그인(캘린더 쓰기 권한) 후 일정을 캘린더에 넣고 Loop B를 시작 |
| 되돌리기 | 마지막 행동 1단계만. 서버 `plans.undo_snapshot` 한 칸 |

## 화면 상태

입력과 결과는 페이지 두 개가 아니라 **한 화면의 상태**다: `input → verifying → result`. 지도는 전체 화면(풀블리드), 패널은 그 위에 뜬다.
